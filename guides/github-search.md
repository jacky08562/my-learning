# 用 GitHub 搜索找知识

GitHub 上有几亿个仓库,但**真正的入口不是首页,是搜索框**。这个文档记录怎么用搜索找到能读的东西。

## 一、先搞清楚:GitHub 上"文章"长什么样

想找"文章""教程""知识",得知道它们在 GitHub 上的载体:

| 你想要的 | 实际在哪儿 | 搜索关键词 |
| --- | --- | --- |
| 文章 / 读书笔记 | 仓库里的 `README.md` 或其他 `.md` 文件 | `in:readme`、`path:*.md` |
| 知识清单 / 资源合集 | 带 `awesome-` 前缀的仓库 | `topic:awesome-list` |
| 系统教程 | 仓库根目录的文档目录 | `in:readme 教程`、`language:Markdown` |
| 代码示例 | 源码文件 | 代码搜索 `path:`、`filename:` |

**关键认知:GitHub 的主语是"项目",不是"文章"。** 所以搜到的东西默认是软件,要往"文档"方向拽,靠的就是限定符。

## 二、核心限定符(照抄就能用)

搜索框里空格分隔多个条件,它们之间是**并且**关系。

### 限定搜索位置

| 写法 | 作用 |
| --- | --- |
| `xxx in:name` | 只搜仓库名 |
| `xxx in:description` | 只搜项目简介 |
| `xxx in:readme` | **搜 README 全文**(找文章最有用) |
| `xxx in:topics` | 只搜标签 |

### 限定数量和活跃度

| 写法 | 作用 |
| --- | --- |
| `stars:>1000` | 星数大于 1000(筛掉没人验证的) |
| `stars:100..500` | 星数在区间内 |
| `pushed:>2026-06-01` | **最近还在更新**(筛掉弃坑的) |
| `created:>2025-01-01` | 创建时间 |
| `forks:>100` | 被 fork 次数 |

### 限定主题和技术栈

| 写法 | 作用 |
| --- | --- |
| `topic:awesome-list` | 按官方标签搜,最准 |
| `language:Markdown` | 主要语言是 Markdown(文档类仓库) |
| `language:Python` | 主要语言是 Python |
| `license:cc-by-4.0` | 许可证(能不能自由传阅) |
| `user:ruanyf` | 某个人的仓库 |
| `org:microsoft` | 某个组织的仓库 |

## 三、实测:裸搜 vs 加限定符

同一个词"理财",三种搜法结果差多少:

| 搜法 | 命中 | 结果质量 |
| --- | --- | --- |
| `理财` | 5,114 个 | 前几名是**电商系统**(README 里恰好出现过这个词) |
| `理财 in:readme stars:>3000` | 157 个 | 前几名出现科技周刊、人生指南,明显更对口 |
| `topic:awesome-list finance` | 108 个 | **全部命中**,`awesome-quant`、`awesome-systematic-trading`、`awesome-ai-in-finance` |

**结论:词越准,限定越狠,结果越少但越能读。** 宁可只有 100 个结果,也不要 5000 个里翻不到。

## 四、三个可以直接抄的组合

```
# ① 找中文知识类仓库,要活的
理财 in:readme stars:>1000 pushed:>2026-06-01

# ② 找资源合集清单
topic:awesome-list 投资

# ③ 找文档型仓库(Markdown 写的教程)
language:Markdown 机器学习教程 stars:>500
```

## 五、其他三个搜索入口

搜索框左边有个下拉菜单,能切换搜索范围:

| 入口 | 能搜什么 | 典型用法 |
| --- | --- | --- |
| **Repositories** | 仓库 | 找项目、找资料(最常用) |
| **Code** | 代码全文(**需登录**) | 搜函数名、配置写法,`path:*.md 复利` |
| **Issues** | 问题和讨论 | **把你遇到的报错粘进来**,命中率比通用搜索高得多 |
| **Discussions** | 社区讨论 | 找"该怎么学""选哪个"这类经验贴 |

## 六、仓库内部的搜索(这个最省时间)

打开任意仓库后:

- 按 `t` → 进入文件查找模式,直接输入文件名跳转
- 按 `/` → 光标跳到仓库搜索框
- 页面顶部的 "Go to file" 也是同一件事

看大仓库时(比如几万个文件),**不要一层层点目录,直接按 `t`**。

## 七、判断一个仓库值不值得读

搜到之后,看四样,十秒钟能判断:

1. **星数** —— 有人验证过
2. **最近更新日期**(页面右上角) —— 还在维护吗
3. **许可证** —— 有没有,能不能自由使用
4. **README 有没有目录** —— 作者是否认真

四条全过,才值得花时间。

## 八、练习任务

用上面的语法,自己找三个仓库,要求:

- [ ] 一个 `topic:awesome-list` 搜出来的清单
- [ ] 一个 `stars:>1000` 且 `pushed:>2026-06-01` 的中文仓库
- [ ] 一个用 `in:readme` 搜某个你关心的具体词找到的

找到后把仓库名记到笔记里,写一句"为什么选它"。
