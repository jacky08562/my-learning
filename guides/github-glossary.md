# GitHub 术语对照表

界面没有中文,但需要记住的词只有三十来个。**建议不要汉化界面**——命令、报错、文档全是英文,汉化界面会让你看得懂界面、连不上现实。

## 一、最核心的六个

| 英文 | 中文 | 一句话 |
| --- | --- | --- |
| **Repository** | 仓库 | 一个项目。所有代码、文件、历史版本都装在它里面 |
| **Commit** | 提交 | 给文件拍一张快照,并写一句"这次改了什么"。**历史的最小单位** |
| **Branch** | 分支 | 从主干分出来的一条独立路线,改坏了不影响别人 |
| **Merge** | 合并 | 把一条分支的改动并回另一条 |
| **Push** | 推送 | 把本地的提交传到 GitHub |
| **Pull** | 拉取 | 把 GitHub 上的新提交取回本地 |

## 二、协作相关

| 英文 | 中文 | 一句话 |
| --- | --- | --- |
| **Fork** | 派生 | 把别人的仓库复制一份到你账号下,你随便改,不影响原仓库 |
| **Pull Request**(PR) | 合并请求 | "我改好了,请你把我的分支合进主干"。**这是 GitHub 的灵魂** |
| **Issue** | 议题 | 一条任务、一个 bug、一个提问。**不是"错误"** |
| **Review** | 审查 | 别人看你的 PR,提意见 |
| **Contributor** | 贡献者 | 往仓库提交过内容的人 |
| **Star** | 收藏 | 点星 = 收藏 + 投票。**不产生任何副本** |
| **Watch** | 关注 | 有动静就通知你(建议只选 Releases) |
| **Discussion** | 讨论 | 不像 issue 那样要"解决",更像论坛帖 |

## 三、命令行常用

| 命令 | 干什么 |
| --- | --- |
| `git clone <地址>` | 把远程仓库完整复制到本地 |
| `git status` | 看当前有哪些改动 |
| `git add -A` | 把改动加入"待提交" |
| `git commit -m "说明"` | 提交,并写说明 |
| `git push` | 推到远程 |
| `git pull` | 拉取远程更新 |
| `git log --oneline` | 看提交历史 |
| `git checkout -b 名字` | 新建并切换到一条分支 |
| `git diff` | 看具体改了哪几行 |

## 四、文件与配置

| 英文 | 说明 |
| --- | --- |
| **README.md** | 仓库的门面。打开仓库第一眼看到的就是它 |
| **.gitignore** | 列在里面的文件**不会被提交**(比如密钥、缓存) |
| **LICENSE** | 许可证。没有它的项目,别人在法律上不能随便用 |
| **Markdown**(`.md`) | 用 `#` `**` `-` 这类符号排版的纯文本。GitHub 会把它渲染成网页 |
| **Raw** | 看文件原始内容(不渲染) |
| **Release** | 打好的版本包,附下载文件 |
| **Actions** | 自动化流程(测试、部署),写在 `.github/workflows/` |
| **Pages** | 把仓库直接变成网站 |
| **Gist** | 存单个代码片段的地方 |

## 五、账号与安全

| 英文 | 说明 |
| --- | --- |
| **SSH key** | 一对钥匙(公钥给 GitHub,私钥留自己机器)。配好后推送不用输密码 |
| **PAT**(Personal Access Token) | 一串令牌,代替密码用。可限定权限和有效期 |
| **2FA** | 两步验证。**手机时间不准会导致验证码永远错误** |
| **OAuth** | 用 GitHub 账号登录别的网站 |

## 六、最容易搞混的五组

| 别混 | 区别 |
| --- | --- |
| **Fork vs Clone** | Fork 是"在 GitHub 上复制一份到你账号";Clone 是"下载到你电脑"。Fork 在云端,Clone 在本地 |
| **Star vs Fork** | Star 只是收藏加投票,不产生副本;Fork 真的复制出一份你可以改的仓库 |
| **Pull vs Fetch** | Fetch 只下载、不合并;Pull = Fetch + 自动合并 |
| **Issue vs PR** | Issue 是"这里有个问题/任务";PR 是"我改了,请你合并" |
| **Commit vs Push** | Commit 只记在**你电脑上**;Push 才发到**GitHub**。只 commit 不 push,别人看不到 |

## 七、一句提醒

看到不认识的词,**别急着搜中文解释**。先在仓库里找它的实际用法——比如搜 `Pull Request` 看看别人怎么写 PR 描述,比看十篇教程都快。
