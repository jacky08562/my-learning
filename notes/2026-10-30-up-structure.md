## 一、它怎么组织的(这部分可以直接抄)

403 个文件,322 个在 `docs/`。分卷结构:

```

docs/threads/part-2/   把自己放回生活(关系、失败、恢复)
docs/threads/part-3/   **借工具放大能力(AI)**
docs/threads/part-4/   实践与恢复(节律、日常)
docs/threads/part-5/   行动与长期改变(90 天)
docs/threads/part-6/   与自己做终身朋友
docs/templates/        27 个可填写的模板
docs/en/               英文镜像(104 个文件)
```

**四个值得偷的设计:**

1. **README 不是简介,是入口分流表**。它第一屏就是"你现在面对的情况 → 先打开哪页 → 一次留下什么"。不知道从哪开始的人,照着表选就行。大多数仓库的 README 只有一句简介,读完还是不知道从哪进。
2. **每部有一个"核心问题",不是一个名词**。比如第三部不是叫"AI 篇",而是"怎样使用 AI,而不把判断力和注意力一起外包?"——**用问题命名,读者立刻知道这一部要解决什么**。
3. **每章配一个模板**。`templates/` 里有 AI 评测记录、创业实验卡、持续行动计划、AI 经历复盘模板。读完必须留下一个填好的东西,而不是"感觉自己懂了"。
4. **多语言镜像放在同一棵树里**(`docs/en/`)。代价是文件数翻倍,好处是结构强制一致。

## 二、挑的那一章:第三部「使用 AI 学习一切」

原文:<https://github.com/byoungd/up/blob/main/docs/threads/part-3/1-ai-learning.md>

### 核心:先做事,再谈提示词

作者给了一个**七步闭环**,顺序是关键:

1. 定义真实结果(场景、受众、动作、截止时间、验收标准)
2. **保存无 AI 基线**:先自己独立做一次,暴露知识缺口
3. 准备可信材料(官方文档、教材、论文、真实案例)
4. 设计引导练习(让 AI 提问、比较、出题,不代替关键步骤)
5. 主动产出(关掉材料,自己解释、写、算、做决定)
6. 多源反馈(AI 只是一个意见;还要看来源、测试、专家、用户)
7. 更新状态(保存作品、错误、成本、未决问题、下一步)

**缺第 1 步,AI 会把愿望包装成答案;缺第 2 步,你不知道能力到底有没有长;缺第 6、7 步,同样的错误下次还会犯。**

### 五个层次:你现在卡在哪一层

| 层次 | 要能解释什么 | 留下什么证据 |
| --- | --- | --- |
| 模型与输出 | 流畅不等于真实 | 找一个它答错的例子 |
| 上下文与检索 | 上下文是本次给的材料 | 用三页文档回答,每条结论标到原文位置 |
| 结构与工具 | 输出格式对,不代表内容真 | 检查缺字段、错数字、工具失败 |
| 工作流与评测 | 步骤、权限、失败处理决定可用性 | 比较人工与 AI 流程,留下失败记录 |
| 学习与迁移 | 有工具的成品质量 ≠ 自己的独立能力 | 隔 3~7 天,换条件、不看旧答案重做 |

### 一次会话的最小协议(可以直接抄去用)

开始时,让 AI **复述边界**,而不是直接干活:

```text
请用不超过 8 条要点复述目标、受众、输入、验收标准、限制、未知项和你无法确认的内容。
列出准备使用的来源。没有来源的事实标记为待核验。
先不要生成最终交付,先指出最可能导致返工的 3 个风险。
```

结束时,要**状态更新**,不要漂亮总结:

```text
根据本次实际完成内容输出:
1. 已完成与证据位置;
2. 已被来源、测试或人工确认的判断;
3. 仍会重复的错误、风险和未决问题;
4. 下一项最小任务、完成标准和需要的材料。
不要声称记得其他会话,也不要把推断写成事实。
```

## 三、跟我今天做的事对照

我今天带你调 API 的过程,正好走的是这个闭环:

| 七步里的哪步 | 今天对应的动作 |
| --- | --- |
| ① 定义真实结果 | "让程序调通一次大模型" |
| ② 无 AI 基线 | 先自己踩坑:打码复制、JWT、文件被覆盖 |
| ③ 可信材料 | 官方文档、实测响应、状态码 |
| ⑤ 主动产出 | 写 `01-first-call.sh`、`02_chat.py` |
| ⑥ 多源反馈 | 三个脚本交叉验证、查提交历史确认没泄露 |
| ⑦ 更新状态 | 写进笔记、提交到仓库 |

**最有价值的恰恰是第 ② 步**——那三个坑是你自己撞出来的,别人讲一百遍你也记不住。

## 四、我原来以为

> 我原来只让 AI "完成什么"——只说终点,不给目标定义,中间也不做任何确认。结果产出的东西看着完整,但经不住推敲。

**这句话对应的是七步闭环里缺掉的两步:**

| 缺掉的步骤 | 后果 |
| --- | --- |
| ① 定义真实结果(场景、受众、验收标准) | AI 把愿望包装成答案;你事后才发现方向从一开始就偏了 |
| ⑥ 多源反馈(来源、测试、专家、用户) | 中间没有检查点,错误一路带到成品,而你还以为它是对的 |

**"经不住推敲"的准确含义**:输出的**流畅度**和**可靠性**是两件独立的事。模型很擅长把不确定的东西写得像结论——这正是它最危险的地方,因为它让你失去了"该去核实"的警觉。

### 补法:把一次委托拆成三问

在把任务交给 AI 之前,先自己回答:

1. **目标**:这个结果给谁用、用来干什么、什么算合格?
2. **边界**:哪些不能动、哪些我不确定、哪些结论必须给出来源?
3. **检查点**:每推进一步,我凭什么判断它是对的?

三个问题里任何一个答不上来,说明**你还没想清楚**——这时候问 AI,只会把混乱放大成一个看起来很完整的答案。

### 一句话

> 写不出"什么算完成",就不要开始让 AI 干活。

## 五、马上能用的一条

下次让 AI 干活前,先发那段"复述边界"的提示词。**只要它复述得不对,你就知道该先纠正什么,而不是等成品做完才发现方向错了。**
